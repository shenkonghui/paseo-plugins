为每个会话聚合"本次会话改动了哪些文件"，效果类似 Cursor 聊天中的变更文件列表。

数据来自聊天时间线中已经存在的编辑类工具调用（Edit / Write 卡片，与内置卡片同源），
不读取 git，因此未提交的、已提交的或非 git 项目中的修改都能看到。当提供方没有在
时间线上报行级差异时，插件的守护进程侧组件会读取该会话对应的本地转录文件（如
~/.qoder-cn/projects 下当前会话的 .jsonl），从编辑工具调用的原始参数与结果中提取
统一 diff 与精确的增删行数用于补齐显示；除此之外不访问任何项目文件。

在某个会话的输入框上方会出现一枚"会话变更"胶囊按钮，显示该会话累计修改的文件数和
增删行数；点击后在侧边面板打开。面板顶部有"文件变更 / 记录点"两个视图。

"文件变更"视图左侧是文件列表（每文件带绿色 +N / 红色 -M 与修改次数），点击任一
文件查看它在本会话里的每一次修改，按时间排列并带有行级差异（红绿高亮、行号、
可折叠上下文的省略行）；顶部有"重新扫描"按钮，会重新拉取该会话的时间线。

"记录点"视图把每次向该会话发送消息的时刻保存为一个记录点（与 CLI 的文件历史
快照同源）：每个记录点列出当时被跟踪的文件及版本，可展开查看文件清单，点"恢复"
并确认后，将把这些文件在该记录点时记录的内容写回工作目录（覆盖当前内容，不依赖
git）。CLI 从未跟踪过的文件不在记录点内，不受恢复影响。

已知边界：

- 只统计编辑类工具调用。通过 Shell 命令改动的文件不会出现，这与时间线中的编辑
  卡片行为一致。
- 行数为各次修改的累计值（churn），不是相对会话开始时的净差异，因为不读取文件
  基线；同一区域反复修改会重复计数。
- Write 类调用按整文件新增展示；若提供方未上报文件内容且本地转录也没有，仅显示
  次数不显示内容。
- 行级差异有两个来源：提供方在时间线上报的数据；本地会话转录补齐。两者都没有时
  （如历史会话的转录已被清理），文件列表与修改次数依然完整，单次修改详情会显示
  工具返回的结果文本，并注明未上报行级差异。
- 提供方把任务类工具调用（如 TaskCreate/TaskUpdate）伪装成编辑详情时（filePath
  为 "file" 等非路径值），会被自动过滤，不会出现在文件列表里。
- 恢复遵循"不删除文件"原则：记录点时尚不存在的文件（会话中新建）会被跳过并在
  结果中列出，不会删除；位于工作目录之外的路径同样会被拒绝。恢复依赖 CLI 的本地
  文件历史备份，若备份被清理则无法恢复对应文件，会按文件如实报告。
